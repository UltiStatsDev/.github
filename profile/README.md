# Ultimate Frisbee Stats

**Ultimate Frisbee Stats** — это современное веб-приложение для ведения статистики по алтимат-фрисби в реальном времени.  
Система ориентирована на удобство для стаффа: быстрый ввод событий, мгновенное обновление статистики, удобная интеграция с другими сервисами и простота масштабируемости.

---

## Основные возможности

- **Фиксация игровых событий в реальном времени** (пасы, голы, перебития, блоки, перехваты, потери и пр.)
- **Персональная статистика по игрокам** (голевые пасы, голы, потери, блоки, перехваты, кэллаханы и др.)
- **Командная статистика**: очки, брейки, эффективность передач, эффективность владения и др.
- **Ведение лога событий** с привязкой к игровому времени (с учетом таймаутов)
- **Импорт и экспорт логов матчей** (форматы: JSON, CSV)
- **Редактирование событий матча** до и после игры
- **Быстрое и удобное UI** (шорткаты, быстрый ввод, отмена событий, повторный ввод)
- **Поддержка расширения списка событий** (например, нарушения, кастомные события)
- **OBS Event Log для трансляций:** лента ключевых событий матча с настройкой оформления и подключением через Browser Source
- **OBS Scoreboard:** табло со счётом, командами и длительностью матча; отдельный эфирный профиль для каждого матча
- **API-документация через Swagger/OpenAPI**

## OBS Event Log для трансляций

**OBS Event Log** — лента ключевых событий матча для прямого эфира. Голы, блоки,
перехваты и кэллаханы появляются в виде плашек поверх видеотрансляции по мере
внесения событий в UltiStats. Оператор ведёт матч, а лента получает обновления
автоматически — отдельно заполнять её в OBS не нужно.

Лента подключается как **источник «Браузер» (Browser Source)** с прозрачным фоном.
В оформлении используются имена и номера участников, маркеры событий и цветовые
акценты команд. Новые плашки появляются сверху и исчезают через заданное время.

### Настройка оформления

Встроенная страница `/obs-admin.html` позволяет выбрать матч, посмотреть
предпросмотр и скопировать готовую ссылку для OBS. Здесь можно настроить:

- **События:** включить нужные категории — голы, блоки, перехваты и кэллаханы.
- **Количество плашек:** от 1 до 20 одновременно.
- **Время показа:** от 1 до 60 секунд.
- **Расположение:** любой из четырёх углов кадра.
- **Оформление:** цвет фона, текста и акценты команд. Цвет команды определяется
  автоматически по её изображению; его можно задать вручную или вернуть в режим «Авто».

По умолчанию включены все категории: **5 плашек, 8 секунд, справа сверху**.
Настройки сохраняются на сервере и после сохранения применяются ко всем открытым
источникам этого экземпляра UltiStats без перезагрузки. Каждая ссылка закреплена
за своим матчем: выбор другого матча в админке меняет только предпросмотр
и копируемую ссылку.

### Подключение к OBS

1. Откройте `/obs-admin.html` на том backend, где ведётся нужный матч,
   и выберите его из списка или укажите UUID.
2. Настройте оформление и нажмите **«Сохранить для всех источников»**.
   Кнопка **«Тестовая плашка только здесь»** проверяет вид в предпросмотре:
   она не создаёт игровое событие и не выводит тест в эфир.
3. Скопируйте ссылку вида `/obs-battle-log.html?matchId=<UUID>`.
4. В OBS добавьте **Источники → + → Браузер**, вставьте полный адрес
   и задайте размер **1920 × 1080**. Положение и масштаб источника меняются в OBS.

После первого открытия или полной перезагрузки источника история матча
не проигрывается: лента ждёт новых событий. При восстановлении прерванного
соединения она сверяет журнал и показывает последние пропущенные события
в пределах установленного лимита.

Функция доступна в сборках backend с поддержкой OBS Event Log.
Текущая версия рассчитана на работу в доверенной сети без авторизации.
Подробности запуска, требования к браузерному источнику и API настроек —
в [документации backend](https://github.com/UltiStatsDev/ultistats-backend#obs-battle-log-и-общие-настройки).

## OBS Scoreboard — табло матча

**Scoreboard уже реализован в backend** и доступен в `master`
после [PR #143](https://github.com/UltiStatsDev/ultistats-backend/pull/143).
Это отдельный источник для OBS: названия и логотипы двух команд, подтверждённый
сервером счёт и длительность матча на прозрачном фоне. Его можно использовать
одновременно с Event Log.

Табло отсчитывает время от фактического начала матча, включая таймауты и перерыв.
После завершения длительность фиксируется; матчи дольше часа отображаются
без сброса минут. При потере соединения сохраняется последнее известное состояние,
а после восстановления табло сверяется с сервером.

### Оформление и подключение

1. Откройте `/obs-admin.html` на backend нужного матча и выберите матч.
2. В блоке **«Табло · выбранный матч»** задайте эфирные названия и цвета команд.
   Доступны автоматические цвета, кнопки **«Поменять стороны»**
   и **«Сбросить профиль»**.
3. Проверьте результат в предпросмотре. Правки и сброс сначала видны только здесь;
   нажмите **«Сохранить табло»**, чтобы применить их к эфирным источникам.
4. Нажмите **«Копировать ссылку табло»**. Добавьте в OBS источник **«Браузер»**,
   вставьте полный адрес вида `http://<backend>/obs-scoreboard.html?matchId=<UUID>`
   и задайте размер **1000 × 160**. Размещение и масштаб настраиваются в OBS.

Профиль табло сохраняется **отдельно для каждого матча** и переживает перезапуск
backend. Сохранение обновляет все источники этого матча без перезагрузки.
Эфирные названия, цвета и смена сторон не изменяют игровые данные, карточки команд
или оформление Event Log. Для другого матча нужно скопировать его ссылку.

## Быстрый локальный запуск backend и Web UI

Нужны **Git, Python 3, работающий Docker с Docker Compose** и SSH-доступ к GitHub.
Репозиторий Web UI приватный: для клонирования нужны права в организации.
Backend и Web UI собираются в контейнерах; устанавливать Java и Node.js
на компьютер для этого варианта не требуется.

### 1. Получить Web UI и запустить backend

Выполните из каталога, где будут храниться исходники:

```bash
git clone git@github.com:UltiStatsDev/ultistats-web-ui.git
cd ultistats-web-ui
scripts/backend.sh start
```

Скрипт сам получает отдельную копию backend на версии из `dev/backend/revision`,
собирает приложение, поднимает PostgreSQL и проверяет API. Текущая зафиксированная
версия содержит Event Log и scoreboard. Это изолированное dev-окружение;
существующий каталог `ultistats-backend` скрипт не использует.
Первая сборка скачивает зависимости и может занять несколько минут.

Если Web UI уже клонирован, перейдите в его каталог и запустите
`scripts/backend.sh start`. Используйте актуальный checkout: ранее собранный
backend сам по себе не получает новые возможности после merge в GitHub.

### 2. Запустить Web UI

Из того же каталога, после успешного запуска backend:

```bash
docker compose --env-file /dev/null -f deploy/web/compose.yaml up --build -d --wait
```

Web-контейнер подключается к созданной backend-сети и проксирует API
и загруженные изображения.

### 3. Открыть приложение

| Компонент | Адрес |
| --- | --- |
| Web UI | [http://127.0.0.1:18010](http://127.0.0.1:18010) |
| API backend, пример списка матчей | [http://127.0.0.1:18080/api/v1/matches](http://127.0.0.1:18080/api/v1/matches) |
| Swagger UI | [http://127.0.0.1:18080/swagger-ui.html](http://127.0.0.1:18080/swagger-ui.html) |
| OpenAPI JSON | [http://127.0.0.1:18080/v3/api-docs](http://127.0.0.1:18080/v3/api-docs) |
| Настройка Event Log и scoreboard | [http://127.0.0.1:18080/obs-admin.html](http://127.0.0.1:18080/obs-admin.html) |

Ссылки эфирных источников формируются в OBS-админке после выбора матча:
`http://127.0.0.1:18080/obs-battle-log.html?matchId=<UUID>` и
`http://127.0.0.1:18080/obs-scoreboard.html?matchId=<UUID>`.

Swagger и OBS-страницы открывайте **на порту backend `18080`**:
Web UI проксирует только `/api` и `/uploads`.
Порты `18080` и `18010` должны быть свободны. Если backend уже работает,
его состояние можно проверить командой `scripts/backend.sh status`.
Проверить наличие scoreboard в собранной версии можно так:

```bash
curl --fail http://127.0.0.1:18080/obs-scoreboard.html
```

Ответ `404` означает, что по этому адресу работает сборка без страницы табло
или запрос отправлен не на backend. Новая версия исходников требует пересборки
приложения.

### Разработка Web UI без контейнера

Для режима разработки нужны Node.js **24.22.1 или новее в ветке 24**
и pnpm **11.25.0**. Backend оставьте запущенным через `scripts/backend.sh`;
вместо web-контейнера выполните из каталога Web UI:

```bash
pnpm install --frozen-lockfile
pnpm dev --host 127.0.0.1 --port 5173 --strictPort
```

Web UI будет доступен на [http://127.0.0.1:5173](http://127.0.0.1:5173),
API по умолчанию проксируется на `http://127.0.0.1:18080`.
Dev-сервер работает, пока открыт этот процесс; остановка — `Ctrl+C`.

### Остановка контейнерного варианта

Из каталога Web UI:

```bash
docker compose --env-file /dev/null -f deploy/web/compose.yaml down
scripts/backend.sh stop
```

Обычная остановка сохраняет базу и загруженные файлы в Docker volumes.
Не добавляйте `--volumes` / `-v`, если хотите сохранить данные.

Если запускаете backend напрямую из его репозитория командой
`docker compose up --build -d`, стандартный порт — **8080**.
Для такого варианта используйте Swagger и OBS-админку на `http://127.0.0.1:8080`,
а Web UI в режиме разработки запускайте с нужным адресом API:

```bash
DEV_BACKEND_ORIGIN=http://127.0.0.1:8080 pnpm dev --host 127.0.0.1 --port 5173 --strictPort
```

Подробности: [локальный backend](https://github.com/UltiStatsDev/ultistats-web-ui/blob/main/docs/development/backend.md),
[Web UI](https://github.com/UltiStatsDev/ultistats-web-ui#окружение-и-запуск),
[backend](https://github.com/UltiStatsDev/ultistats-backend#быстрый-старт).

## Текущая реализация ядра

Микроядро на Kotlin (Spring Boot):

- **Только статeless-логи:** события — first class citizen, вся статистика построена на их агрегации
- Простая расширяемая модель событий (sealed class/интерфейсы)
- Вся статистика вычисляется поверх лога событий, никаких дублирующихся состояний
- Временная модель: ведётся "игровое время", поддержка пауз/таймаутов (время “на паузе” не учитывается)
- Шаблоны экспорта/импорта: JSON (event log + match meta)

---

## Технологический стек

- **Backend:** Kotlin, Spring Boot, Gradle
- **Тесты:** JUnit 5, MockK, AssertJ, SpringMockMvc
- **Документация API:** springdoc-openapi (Swagger UI)
- **Логирование:** Logback
- **Frontend:** ReactJS (реализация отдельно)
- **Форматы обмена:** JSON (основной), в перспективе — CSV для табличных статистик

---

## Структура событий

- **Атака:** владение, пуллы, передачи (от кого — кому), голевые пасы, голы, потери (на броске/приёме), спасения
- **Защита:** блок на маркере, перебитие, перехват, кэллахан
- **Системные:** таймауты (старт/конец), начало/конец матча

Каждое событие содержит: тип, команду, время, связанных игроков, доп.параметры (гол, спасение и т.д.)
